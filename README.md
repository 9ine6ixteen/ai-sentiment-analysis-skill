# AI Sentiment Analysis Skill

用于中文评论情感研究的可配置AI工作流，适合研究方法课程、固定样本分析及SPSS与AI的比较。分享版1.1.1。

## 最简单的使用方式

1. 安装skill。
2. 在支持本地skill和文件处理的Codex环境中，上传自己的Excel或CSV。
3. 输入：`使用 $ai-sentiment-analysis 分析这份评论数据。`
4. 告诉AI研究对象和要做的任务；已有人工核验标签时，说明“保留原标签，不重新编码”。

例如：

> 使用 $ai-sentiment-analysis，对这份人工核验的数据做情感频数、点赞数描述统计、方差分析和情感×阶段卡方检验，导出表格和报告。

不需要每次写长提示词。首次使用时仍需确定研究对象、分类规则和统计任务；skill不会擅自选择一套检验。

## 安装

解压分享包，将整个 `ai-sentiment-analysis` 文件夹复制到本机Codex的skills目录。默认位置为 `~/.codex/skills/`；自定义CODEX_HOME时使用其下的skills目录。然后新开对话，确认能选择或调用 `$ai-sentiment-analysis`。

也可把这个完整文件夹交给Codex，要求“帮我安装这个skill”。只有普通聊天且没有本地skill、文件和运行工具的环境，无法把压缩包直接当成可执行软件。

## 数据准备

一条评论一行，保留唯一编号。示例字段：

| 字段 | 含义 | 何时需要 |
| --- | --- | --- |
| sample | 唯一样本编号 | 匹配及复核 |
| comment_text | 评论原文 | 情感编码或文本分析 |
| emotion | 已有情感标签 | 人工核验分析模式 |
| likes | 点赞数 | 点赞描述或差异分析 |
| phase | 事件阶段 | 阶段交叉分析 |

列名可通过配置调整。示例编码为1正面、0中性、-1负面；不强制所有研究采用此编码。阶段需要有时间与事件依据，不自动虚构。

`examples/合成演示数据.csv`是8条人工编写的虚构示例，只用于熟悉字段与调用，不足以做正式统计推断。分享包不含真实微博样本。

## 两种模式

- `code_and_analyze`：未编码文本。先确定编码规则，再判断相关性、评价对象和情感，保留理由及待复核项。
- `analyze_reviewed`：已有人工核验标签。沿用标签，跳过重新情感编码，执行指定统计分析。

固定流程：读取数据 → 确定范围 → 识别评价对象 → 情感编码 → 质量检查 → 统计分析 → 导出。人工核验模式跳过重新编码。

## 当前能力与边界

已包含工作流说明、JSON配置示例、配置与编码结果结构校验脚本。频数、图表、ANOVA、卡方等分析由AI根据任务调用可用计算工具完成。

这不是新的情感算法，也不是安装后即可脱离AI独立运行的软件。`scripts/`里的两个脚本是结构校验器，不是完整分析引擎。统计分析与图表依赖宿主环境的相应库；Excel和PDF输出还需可用的文件生成能力。结果必须实际执行，不能让模型凭空生成统计数值。

LDA、回归和主题×情感匹配可以作为另行配置的工具任务；本包未内置此前课程数据专用的完整分析脚本，不承诺默认自动完成这些扩展。

## 检查是否正确

- 先核对样本数、唯一编号和标签频数。
- 对新情感编码做人工抽查，区分非研究对象内容、无法判断和中性。
- 与SPSS比较时，统一数据、标签、缺失值处理和模型自变量。
- 保留配置、分析代码、运行信息和输出；规则改动需记录版本。
- 小样本、稀疏单元格、点赞偏斜及同一原帖评论的相关性会影响推断。

## 文件结构

- `ai-sentiment-analysis/SKILL.md`：工作流入口。
- `agents/openai.yaml`：显示名称。
- `references/`：字段规范与配置规则。
- `assets/`：未确认的二分类、三分类配置示例。
- `scripts/check_config.py`：配置结构校验。
- `scripts/validate_results.py`：新编码结果结构校验。
